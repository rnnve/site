## Special Custom Tags

These are custom components available in all MDX files.

### `<Rainbow>`

Animated rainbow gradient text.

<Rainbow>This text has a rainbow gradient animation</Rainbow>

**Usage:**
```mdx
<Rainbow>Your text here</Rainbow>
```

### `<Neutral>`

Animated neutral (grayscale) gradient text.

<Neutral>This text has a neutral gradient animation</Neutral>

**Usage:**
```mdx
<Neutral>Your text here</Neutral>
```

### `<Pink>`

Pink colored text.

<Pink>This text is pink</Pink>

**Usage:**
```mdx
<Pink>Your text here</Pink>
```

### `<Color>` / `<color>`

Sets the text color. Accepts CSS color names (e.g. `Aqua`, `Purple`, `Green`) or hex codes — with or without the leading `#`.

<Color color="Aqua">This text is aqua</Color>

<color color="Purple">This text is purple</color>

<Color color="Green">This text is green</Color>

<Color color="#f58bcb">This text is #f58bcb</Color>

<Color color="ff0066">This text is ff0066 (auto-prefixed with #)</Color>

<Color color="#8ef0c0" href="https://github.com/rnnve">This colored text is a link</Color>

**Usage:**
```mdx
<Color color="Aqua">Your text here</Color>
<color color="#f58bcb">Hex codes work too</color>
<Color color="ff0066"># is optional for hex</Color>

{/* Renders as a link when `href` is set */}
<Color color="Aqua" href="https://example.com">Colored link</Color>
```

**Props:**
| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `color` | string | Yes | CSS color name or hex code (with or without `#`) |
| `href` | string | No | When set, renders the colored text as a link |
| `target` | string | No | Anchor target. Defaults to `_blank` for `http(s)` URLs |
| `rel` | string | No | Anchor rel. Defaults to `noopener noreferrer` for `http(s)` URLs |

> **Note:** Both `<Color>` (capitalized) and `<color>` (lowercase) are supported. When `href` is set the text renders as an `<a>` with the same color styling.

### `<Time>`

Displays the current time. Updates every second.

**Visitor's local time (auto-detected timezone):**
<Time />

**With seconds:**
<Time showSeconds={true} />

**Specific timezone:**
<Time zone="America/New_York" />

**Specific timezone (Tokyo):**
<Time zone="Asia/Tokyo" />

**Short format:**
<Time format="short" />

**Time only format:**
<Time format="time-only" />

**UTC time:**
<Time zone="UTC" />

> **Note:** The component must be capitalized as `<Time>` because `<time>` (lowercase) is a native HTML element and will not work as a custom component.

**Usage:**
```mdx
{/* Visitor's local time */}
<Time />

{/* With seconds */}
<Time showSeconds={true} />

{/* Specific IANA timezone */}
<Time zone="America/New_York" />
<Time zone="Asia/Tokyo" />
<Time zone="Europe/London" />

{/* Format options */}
<Time format="full" />      {/* Default: "Mon, Jan 15, 2025, 14:30 (PST)" */}
<Time format="short" />     {/* "Jan 15, 14:30 (PST)" */}
<Time format="time-only" /> {/* "14:30 (PST)" */}

{/* With seconds enabled */}
<Time format="full" showSeconds={true} />      {/* "Mon, Jan 15, 2025, 14:30:45 (PST)" */}
<Time format="time-only" showSeconds={true} /> {/* "14:30:45 (PST)" */}

{/* Combined */}
<Time zone="UTC" format="time-only" />
```

**Props:**
| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `zone` | string | Auto-detected | IANA timezone (e.g., "America/New_York") |
| `format` | "full" \| "short" \| "time-only" | "full" | Display format |
| `showSeconds` | boolean | false | Show seconds in time |

**Common IANA Timezones:**
- `America/New_York` (EST/EDT)
- `America/Los_Angeles` (PST/PDT)
- `America/Chicago` (CST/CDT)
- `America/Denver` (MST/MDT)
- `Europe/London` (GMT/BST)
- `Europe/Paris` (CET/CEST)
- `Asia/Tokyo` (JST)
- `Asia/Shanghai` (CST)
- `Asia/Dubai` (GST)
- `Australia/Sydney` (AEST/AEDT)
- `UTC` (Coordinated Universal Time)

### `<HoverTooltip>`

Displays a tooltip/popup on hover with additional information or a link.

```mdx
<HoverTooltip content="This is a tooltip with additional information">
  Hover over this text
</HoverTooltip>

<HoverTooltip content="https://github.com" href="https://github.com">
  Hover for GitHub link
</HoverTooltip>
```

**Live examples:**

**Basic tooltip:**
<HoverTooltip content="This is a tooltip with additional information">Hover over this text</HoverTooltip>

**Tooltip with link (inline):**
Hover me for <HoverTooltip content="https://github.com" href="https://github.com">GitHub</HoverTooltip> link.

**Props:**
| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `content` | string | Yes | Text to display in the tooltip |
| `href` | string | No | Optional URL to make the tooltip a link |

### `<CFlag>` / `<cflag>`

Displays a country flag using a 2-letter country code (ISO 3166-1 alpha-2).

```mdx
<CFlag>TH</CFlag>
<cflag>US</cflag>
<cflag>JP</cflag>
```

**Live examples:**

<CFlag>TH</CFlag> Thailand
<cflag>US</cflag> United States
<cflag>JP</cflag> Japan
<cflag>DE</cflag> Germany
<cflag>FR</cflag> France
<cflag>BR</cflag> Brazil
<cflag>AU</cflag> Australia
<cflag>CA</cflag> Canada

> **Note:** The component accepts both `<CFlag>` (capitalized) and `<cflag>` (lowercase) syntax. The country code must be a valid 2-letter ISO code.

**Usage:**
```mdx
{/* Capitalized */}
<CFlag>TH</CFlag>

{/* Lowercase */}
<cflag>US</cflag>
```

**Props:**
| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `children` | string | Yes | 2-letter country code (e.g., "TH", "US", "JP") |
| `className` | string | No | Additional CSS classes |

## Widgets

These components are imported from `@/components` in your MDX files. Each accepts an optional `placement` prop that pins it to a corner (or edge) of the viewport.

```mdx
import { DiscordProfile } from "@/components/DiscordProfile";
import { Spotify } from "@/components/Spotify";
import { SocialLinks } from "@/components/SocialLinks";

<DiscordProfile userId="1" compact placement="top-right" />
<Spotify placement="bottom-left" />
<SocialLinks placement="bottom-right" />
```

**`placement` values:**

| Value | Position |
|-------|----------|
| `top-left` | Top-left corner |
| `top-center` | Top center |
| `top-right` | Top-right corner |
| `bottom-left` | Bottom-left corner |
| `bottom-center` | Bottom center |
| `bottom-right` | Bottom-right corner |

> **Note:** Omit `placement` to keep the widget in the normal document flow (the default). For `SocialLinks`, the default behavior is a centered inline row on small screens that becomes a fixed vertical rail on `lg` and up; setting `placement` replaces that rail with the chosen position.
>
> `Spotify` renders nothing unless a track is actively playing, so its example above only appears while you're listening.

### `<SocialLinks>` size & spacing

`SocialLinks` also accepts `size` (icon + button diameter) and `spacing` (gap between icons) presets.

```mdx
<SocialLinks size="lg" spacing="sm" />
<SocialLinks size="sm" spacing="xl" placement="top-right" />
```

**`size` values:**

| Value | Icon | Button |
|-------|------|--------|
| `sm` | 16px | 36px |
| `md` | 20px | 44px |
| `lg` | 24px | 48px |
| `xl` | 28px | 56px |

**`spacing` values:**

| Value | Gap |
|-------|-----|
| `none` | 0 |
| `sm` | 4px |
| `md` | 8px |
| `lg` | 12px |
| `xl` | 16px |

> **Defaults:** `size` uses the responsive 44px button (40px on `lg`) with a 20px icon; `spacing` uses `6px`. Both `size` and `spacing` are independent of `placement` and can be combined.

### `mobile-` overrides

Any of the props above can be given a different value on mobile with a `mobile-` prefixed variant. These apply below the `lg` breakpoint (the site's mobile layout).

```mdx
{/* bottom-right on desktop, top-right on mobile */}
<DiscordProfile userId="1" compact placement="bottom-right" mobile-placement="top-right" />

<SocialLinks
  placement="bottom-right" mobile-placement="top-left"
  size="lg" mobile-size="sm"
  spacing="lg" mobile-spacing="none"
/>
```

| Prop | Mobile override | Applies to |
|------|-----------------|------------|
| `placement` | `mobile-placement` | `DiscordProfile`, `Spotify`, `SocialLinks` |
| `size` | `mobile-size` | `SocialLinks` |
| `spacing` | `mobile-spacing` | `SocialLinks` |

> **Note:** The prefix uses a dash (`mobile-placement`), not a colon. JSX namespaced attributes like `mobile:placement` are rejected by the compiler because React does not support them.

## Combining Elements

You can combine custom tags with regular markdown:

<Rainbow>**Bold rainbow text**</Rainbow>

<Neutral>*Italic neutral text*</Neutral>

<Pink>`Inline code in pink`</Pink>

<Underline>~~Strikethrough with underline~~</Underline>

## Escaping

To display the literal tag names without rendering them, use backticks:

- `` `<Rainbow>` `` renders as: <Rainbow>rainbow text</Rainbow>
- `` ` \`<Rainbow>\` ` `` renders as: `` `<Rainbow>` ``
